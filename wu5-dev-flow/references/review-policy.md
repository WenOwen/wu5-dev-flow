# 审查规范

## 两轮审查

先完成规格符合性审查，再完成代码质量审查。不要混为一次泛化检查。

### 规格符合性

- 对照需求 ID、场景、非目标和验收标准检查实现。
- 检查测试是否覆盖每个新增或修改需求。
- 检查是否出现未批准功能、依赖、接口或范围扩大。

### 代码质量

- 检查正确性、边界、错误处理、类型、安全、可维护性和回归风险。
- 检查测试是否锁定稳定行为而非内部实现。
- 检查日志、异常和验证摘要是否泄露敏感信息。
- 逐项检查新增字面量，禁止写死环境值、路径、URL、敏感信息、业务策略和魔法数字；合理常量必须命名并说明来源。

## 独立复审

出现任一情况时调用独立 Codex 代理：安全或认证、公开契约、并发、持久化格式、跨三个以上顶层模块。给复审代理原始规格、diff 和验证证据，不泄漏先前结论。

代理不可用时，披露降级，并在清空先前结论后分别重做规格与质量审查。把两轮结果写入 `verification.md`：

```text
- [x] 规格符合性审查
- [x] 代码质量审查
- [x] 未引入不当 hardcode
- [x] 独立复审（不适用时写明原因）
```
