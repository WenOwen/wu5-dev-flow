# 00 环境：先让工具链能工作

在新项目接入、安装失败或环境不一致时读取。已能运行和验证的老项目只补本次缺口。

## 值得保留的见解

- **环境混乱会耗尽开发精力。** 先确认终端、Git、项目运行环境与一个主要 AI 工具可用，再开始实现；不要一直比较工具而没有跑通项目。
- **Git 是恢复点。** 在业务变更前检查仓库与已有改动，让每个小结果能比较和恢复。保护用户工作，不为获得干净状态自动清空工作区。
- **装上不等于接通。** 用版本命令、项目启动和最小检查核实工具；Agent 还要能读到正确仓库、规则与文件。
- **环境服务于技术方案。** 网站的 Node.js、Next.js 是 Web 示例。已有项目遵循声明的运行版本；新项目先准备基础工具，技术方案确定后再选脚手架。
- **能复现比“我这里能跑”更重要。** 核实依赖清单、锁文件、运行版本和启动入口；不要把安装路径、个人目录或秘密写入共享文档。

## 执行与交接

检查已有 README、依赖声明和 CI，再运行实际可用的版本、启动与验证命令。缺什么就解决什么，不批量安装新工具。新依赖和外部操作仍遵循已有授权。

关键命令写入 AGENTS.md；临时故障与下一步写入 memory.md。能启动或执行核心入口、能运行适用检查后，进入调研或当前任务。没有 UI 的技能或库不要求 localhost。
