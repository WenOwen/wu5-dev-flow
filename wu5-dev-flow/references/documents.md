# 短文档样例

只在需要写对应文档时使用。下面是写法示例，不能把示例里的需求、命令、状态或验证结果当成项目事实。按实际情况改写，删掉不适用的部分；已有等价文件直接更新。

每份项目文档含标题、命令和链接不超过 500 个非空白字符。内容太多时收敛当前范围、压缩结论，把细节指向原始证据；不另建摘要、索引、变更包、验证报告或历史副本。

## 旧版项目接入

用户要求切换流程时，从旧 `spec/` 提炼当前范围、重要设计和未完成任务，写入对应文档并核实代码与测试。仅替换 AGENTS 中 `<!-- wu5-dev-flow:start -->` 到 `<!-- wu5-dev-flow:end -->` 的旧说明块，保留其他规则；没有明确边界时先指出冲突。旧规格保留供查阅，不继续维护两套状态，不运行 `wu5_flow.py`。

## docs/research.md · 需要验证问题时

```markdown
# 调研：每日跑步打卡

## 问题
想保持跑步习惯的人需要快速打卡，现有流程操作太多。

## 依据
2026-10-13：提出者描述了自己的使用痛点，尚无其他用户访谈。
替代方案：日历勾选；已能打卡，但连续天数需要手算。

## 结论
先验证“一键打卡＋连续天数”是否值得做。

## 未知与下一步
找两位目标用户试用纸面流程，询问是否比现有方法省事。
```

联网调研保留少量直接支持结论的来源链接和日期。没有证据写假设，读不到来源就说明限制。

## docs/prd.md · 需要明确产品范围时

```markdown
# PRD：RunStreak

## 用户
想每天跑步、不打断习惯的人。

## 目标
一键记录今天跑过，立即看到连续天数。

## 为什么
只关注打卡习惯，让记录比日历手算更方便。

## MVP
1. 登录以保存记录。
2. 一键打卡今天，重复点击不重复计数。
3. 显示连续天数；漏一天后重新计数。

## 不做
GPS、社交、里程、配速、通知。

## 成功标准
新用户在 30 秒内登录、打卡并看到连续天数为 1。
```

PRD 写目标范围；尚未实现的内容不能标成已交付。修复实现偏差不用改 PRD，改变产品行为时更新相应条目。

## docs/design.md · 确定产品技术选型时

```markdown
# 技术设计：RunStreak

## 框架
Next.js（App Router），适合小型 Web 应用并方便部署。

## UI
Tailwind CSS + shadcn/ui，覆盖单页打卡界面。

## 数据库与登录
Supabase，统一提供 Postgres 和身份认证。

## 数据模型
runs：id、user_id、run_date、created_at。用户与日期联合唯一；日期按用户时区确定，连续天数从记录计算。

## 部署
Vercel，连接 Git 仓库构建部署。
```

技术设计先写产品的技术选型与理由、数据模型、部署方式；老项目记录已采用的技术。按产品形态调整栏目：CLI 或技能可写运行环境、文件结构与分发方式，适用时补充验证策略。单次任务的清单与验收结果放 memory，避免另建过程文件。测试驱动开发简称 TDD。

## docs/memory.md · 多步任务或需要交接时

```markdown
# 当前进度

## 目标与任务
打通当天打卡。
- [x] 重复点击不新增记录。
- [ ] 显示连续天数。

## 决定
保留现有登录服务；日期按用户选定时区计算。

## 最新验证
任务“重复打卡”，commit abc1234：
`npm test -- checkin.test.ts`：8 项通过；写实现前观察到重复计数断言失败。

## 问题与下一步
尚未验证跨时区切换。下一步先写漏日后重新计数的测试。
```

只记录实际观察到的结果。未提交时写任务或改动范围，不编造 commit。续接时核实 Git 和测试，源码变化后重新验证。压缩已完成任务，不把每次 RED/GREEN 输出逐条落盘；保留少量有效决定及理由，稳定结论移回 PRD 或设计。

## docs/release.md · 准备发布时

```markdown
# 发布：0.1.0

## 候选与状态
commit abc1234；准备完成，尚未部署。
内容：登录、当天打卡、连续天数。

## 验证与风险
候选版本测试、构建通过；尚未验证目标环境登录回调。

## 执行与恢复
用现有流水线部署候选，核实登录回调配置。
冒烟：登录→打卡→刷新→重复打卡。
失败时恢复上一制品；涉及数据变化时先明确兼容与恢复方案。

## 用户交付
说明如何打卡；反馈入口为项目 issue。
```

按交付形式写步骤：服务检查真实环境，CLI 检查运行与退出码，库或技能检查安装与调用。发布后更新实际版本、时间和验收结果。只记录当前发布，历史留给 Git、现有发布系统；反馈汇总到 memory，下一轮只改受影响文档。

## AGENTS.md · 缺少稳定开发入口时

```markdown
# 项目开发

每日跑步打卡 Web 应用。

## 命令
开发：`npm run dev`
测试：`npm test`
构建：`npm run build`

## 约定
沿用现有登录与日期模块。不得把用户时区替换为服务器时区。

## 上下文
先读 docs/memory.md；按任务查 docs/prd.md 和 docs/design.md。
每次完成一个验收场景，测试通过后提交；结束前更新下一步。
```

命令必须来自实际项目配置并核实。合并进现有规则，不整文件覆盖；不写本机 Skill 绝对路径、动态进度或聊天记录。只有规则变化时更新。
