# 04 上下文：让新会话继承决定

在首次建立开发入口、换会话接手、上下文变长或任务偏航时读取。

## 值得保留的见解

- **聊天不是可靠的项目状态。** 新会话需要能从文件与代码恢复目标、选型、规则和下一步，不能要求用户反复讲历史。
- **一个事实只有一个主要位置。** AGENTS 保存稳定规则与入口，PRD 保存需求，TechDesign 保存技术方案，memory 保存当前任务。用引用关联，不把需求复制进所有文件。
- **上下文随项目成长。** 空项目不需要不存在的架构图；有真实代码后再记录关键模块与共享工具的位置，帮助复用而非重复造轮子。
- **文件名和符号没有自动魔法。** 不同 Agent 的加载方式不同。核实宿主实际读取的入口，避免维护内容相同的多份规则；未经核实不能声称某个导入符号一定生效。
- **恢复时核对现实。** 阅读规则与当前任务，检查 Git、源码和检查命令，再用几句话说明目标与下一步；过期 memory 不能覆盖实际代码。
- **偏航先重新锚定。** 比较原请求、实际差异和未授权扩展，定位偏差再继续；不要在错误理解上不断补丁。长会话先整理决定、未知项与下一步，再按需要换会话。
- **交接要有人维护。** 任务完成后更新结果与下一步，压缩过期记录。保留经验的原因和适用条件，不把偶然失败升格为永久禁令。

## 执行与交接

新会话应能说出产品目标、当前任务、稳定技术选择与验收方式。不能正确复述时先补最少的缺失事实；测试恢复能力需要真实新会话，当前作者自检不能冒充独立验证。

```markdown
# 项目开发
每日跑步打卡 Web 应用。
## 命令
开发：`npm run dev`；测试：`npm test`；构建：`npm run build`。
## 约定与入口
沿用现有登录与日期模块；按用户时区计算日期。
先读 docs/memory.md，按任务查 docs/PRD.md 和 docs/TechDesign.md。
```

```markdown
# 当前进度
## 任务与决定
当天打卡已完成，下一项是连续天数；沿用现有登录服务。
## 最新验证
任务“重复打卡”，commit abc1234：目标测试 8 项通过，写实现前观察到重复计数断言失败。
## 问题与下一步
跨时区切换尚未验证；先写漏日后重新计数的测试。
```
