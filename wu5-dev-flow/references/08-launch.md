# 08 用户交付：去用户已经在的地方

在准备上手说明、首批用户、发布材料或选择分发渠道时读取。外部发帖、通知和私信仍需已有授权。

## 值得保留的见解

- **可访问不代表被采用。** 把产品交给目标用户是独立工作：他们在哪里、为何愿意点开、如何快速获得核心价值，需要有明确答案。
- **先专注一个合适的渠道。** 同时铺很多平台容易无法判断哪个有效。先选目标用户已有交流的地方，做一个可检查的小实验，再决定扩展或停止。
- **先讲问题与结果。** 说明为谁解决什么、如何使用以及当前限制，配一张核心结果或简短演示；泛泛的“看看我的应用”无法让用户判断是否相关。
- **社区规则与语气属于产品交付。** 阅读当前渠道规则，贡献有用信息并认真回应问题；不要跨平台复制同一份话术，更不以诱导投票或刷量替代真实采用。
- **按来源观察有效使用。** 适用时用 UTM、反馈入口或来源问题区分渠道。观看量、点赞与安装不同，继续看用户是否完成核心动作并再次使用。
- **说明和第一屏决定能否理解。** 用户只看标题、截图或 README 开头，也应知道产品价值与第一步。不要把内部实现细节塞进面向用户的入口。
- **付费产品先说明价值与边界。** 定价、免费额度、试用和退款带来的困惑可影响信任；通过实际用户反馈验证，不复制网站给出的固定价格、转化率或人数经验。

## 执行与交接

写一个渠道的使用说明、价值陈述、演示与反馈入口，制定观察方式和检查时间。只在授权范围内对外执行；暂未获授权时交付可审阅材料。

将当前交付与渠道结果简记在 release 或 memory，不新建营销流水账。获得真实使用与反馈后进入迭代；低样本下保持不确定性，不把一次曝光当成产品验证。
